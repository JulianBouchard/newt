## Also included

<div class="newt-cases">

<div>

### [Steering](events/)

A message that arrives during a turn joins it between model calls.

</div>

<div>

### [Exactly-once outward calls](tools/#make-outward-calls-exactly-once)

Outward calls are recorded in Postgres before they run and retried with the same idempotency key after a crash.

</div>

<div>

### [Compaction](memory/)

Past a token budget, the agent writes a checkpoint of its history. A checkpoint that drops an open commitment is rejected. Raw history is kept.

</div>

<div>

### [Cache report card](tracing/)

`newt-report` lists every prompt cache miss and its cause: a changed tool, compaction, an idle gap or routing.

</div>

<div>

### [Replay and fork](replay/)

Copy a real conversation into a new session and run it against another prompt or model, turn by turn.

</div>

<div>

### [MCP-only agents](mcp-agents/)

An agent can be a single MCP server. Its instructions, tools and resources are the agent.

</div>

<div>

### [Model fallback](configuration/#modelsalias)

Each model is a chain of routes: Anthropic, OpenAI or any Chat Completions host. A failed call retries, then moves to the next route.

</div>

<div>

### [Several instances](design/#the-postgres-runner)

One binary and Postgres. Any instance can run any session.

</div>

</div>

## Already have an MCP server?

<NewtPlusMcp />

Point newt at it with `mcp = "https://…"` in `server.toml`. The server's instructions, tools and resources become the agent. [MCP-only agents](mcp-agents/) has the details.

## Try it with Docker

A fake model answers, so you don't need an API key.

```sh
docker compose -f deploy/compose.yaml up --build -d
curl -X POST localhost:7878/v1/agents/assistant-mcp/sessions/ana/events \
  -H "Authorization: Bearer demo-token" -H 'content-type: application/json' \
  -d '{"id":"m1","text":"Remind me to call the bank tomorrow."}'
curl -N localhost:7878/v1/agents/assistant-mcp/sessions/ana/live -H "Authorization: Bearer demo-token"
```
