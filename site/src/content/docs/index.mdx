## What else you get

<div class="newt-cases">

<div>

### [Follow-up messages join the turn](events/#send-an-event)

If the person writes again while the agent is working, the new message joins the turn before the agent replies.

</div>

<div>

### [No double sends](design/#how-a-message-never-gets-sent-twice)

Messages, emails and payments are written down in Postgres before they go out, so a crash never sends them twice.

</div>

<div>

### [Long conversations stay short](design/#what-happens-when-history-gets-long)

When history gets too long, the agent writes a checkpoint. A checkpoint that forgets a promise gets refused, and nothing is ever deleted.

</div>

<div>

### [See every cache miss](tracing/)

`newt-report` shows every prompt cache miss and what caused it: a changed tool, compaction, a long pause or routing.

</div>

<div>

### [Re-run real conversations](replay/)

Copy a real conversation into a new session and run it against another prompt or model, turn by turn.

</div>

<div>

### [Any MCP server works](agent-core/)

Your agent is an MCP server, plus any extra servers it pulls in. newt reaches them over HTTP or runs them itself.

</div>

<div>

### [Falls back to another model](configuration/#modelsalias)

Each model is a list of providers: Anthropic, OpenAI or anything that speaks Chat Completions. A failed call retries, then moves to the next one.

</div>

<div>

### [Run as many instances as you like](design/#running-several-instances)

One binary and Postgres. Run as many instances as you like, any of them can run any session.

</div>

</div>

## Your agent is an MCP server

<NewtPlusMcp />

Write it with any MCP SDK, or use one you already have. Point newt at it with `mcp = "https://…"` in `server.toml`, or let newt run it with `mcp = "stdio:…"`. Its instructions, tools and resources become the agent. Add the `newt` extension and it also picks the model and steers each turn. [Build your agent](agent-core/) has the details.
